# 1. The first thing I'd install: Superpowers

[Superpowers GitHub repository](https://github.com/obra/superpowers?utm_source=chatgpt.com)

This is probably the single most valuable addition.

It is not really "one agent". It is a **software development methodology implemented as composable skills**.

It supports OpenCode directly. ([GitHub][2])

The workflow is essentially:

```text
Requirement
    ↓
Brainstorm
    ↓
Design
    ↓
Implementation plan
    ↓
TDD
    ↓
Subagent implementation
    ↓
Review
    ↓
Verification
    ↓
Completion
```

That is exactly what I want for production backend work.

Particularly useful:

```text
brainstorming
writing-plans
executing-plans
test-driven-development
subagent-driven-development
systematic-debugging
requesting-code-review
receiving-code-review
verifying-before-completion
using-git-worktrees
```

The important philosophy is:

> don't let the agent immediately start coding.

It forces specification, planning, implementation and verification into separate stages.

For a bank environment, that's a **feature**, not overhead.

# 16. Don't install everything

This is important.

OpenCode itself warns that MCP servers add model context and that enabling too many tools can rapidly consume context. ([OpenCode][9])

Same principle applies to agents.

You don't want:

```text
66 skills
+
40 agents
+
20 MCPs
+
100 commands
```

all active all the time.

You'll create:

```text
tool noise
routing ambiguity
context bloat
slower decisions
wrong skill selection
higher token consumption
```

There is also emerging research around this exact problem. A recent analysis of 138,133 public `SKILL.md` files found that 91.8% contained at least one detected defect, with weak routing metadata and bloated/non-actionable skill bodies among the dominant problems. ([arXiv][11])

So **more skills ≠ better agent**.

Curated skills > massive skill dump.
